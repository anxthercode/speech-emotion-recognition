# Определение эмоций человека по голосу

Дисциплина — «Основы машинного обучения». Полный проект Галкина В. А. и Леончука Е. Д.
Цель — сравнить CNN на Log-Mel, вероятностный GMM на MFCC и SVM на статистиках MFCC.
Разбиения и условия шума общие для всех моделей.

## Этап 1. Данные и признаки

### 1.1. Проверенный CREMA-D

[CREMA-D](https://github.com/CheyneyComputerScience/CREMA-D) содержит 7 442 записи, 91 диктора,
6 эмоций. Речь постановочная, англоязычная, 12 фраз. Используем заданную эмоцию из имени файла,
не смешиваем её с оценками слушателей. Например, `1001_DFA_ANG_XX.wav` — диктор 1001, фраза DFA,
эмоция ANG, интенсивность XX.

Аудит уже исключил 7 файлов: один беззвучный и шесть файлов в трёх парах одинакового аудио
с противоречивыми метками. Остаётся **7 435 записей от 91 диктора**. Пороги, причины и хеши
сохранены в `data/metadata.csv`, `data/exclusions.csv`, `data/crema_audio_audit.json`.
Исходные WAV не изменяются. Перед подготовкой повторно проверяется SHA-256 каждого файла.

Порядок классов: ANG=0, DIS=1, FEA=2, HAP=3, NEU=4, SAD=5.

### 1.2. Два разбиения

**Speaker** — основной протокол. Отсортированные дикторы переставляются NumPy PCG64 с seed=42.
Первые 14 идут в test, следующие 14 — в validation, оставшиеся 63 — в train. Все записи диктора
остаются в одной части. Списки дикторов сохраняются.

**Random** — контрольный протокол. Записи стратифицируются по эмоциям при тех же количествах
train/validation/test, что получены в speaker. Квоты классов рассчитываются пропорционально методом
наибольших остатков, при равенстве — по фиксированному порядку классов. Сначала выделяется test,
затем validation из остатка. В этом протоколе дикторы могут быть общими между частями.

Разбиваем исходные файлы до окон и шума. Проверяем покрытие всех пригодных файлов ровно один раз,
отсутствие пересечений file_id и SHA-256, наличие шести классов в каждой части и отсутствие общих
дикторов для speaker. Разбиение не подбирается по будущим метрикам моделей.

### 1.3. Log-Mel для CNN и GUI

Общий конвейер: `WAV → mono → 16 kHz → окно → STFT → мощность → Mel-фильтры → dB`.

| Параметр | Значение |
|---|---:|
| Частота | 16 000 Hz |
| CNN-окно | 4 с, 64 000 отсчётов |
| FFT / periodic Hann / hop | 512 / 400 / 160 |
| Центрирование | `center=False` |
| Mel | 64 полосы, HTK, Slaney area normalization |
| Диапазон | 50–7 600 Hz |
| Спектр | `abs(STFT)²` |
| Логарифм | `10 log10(max(M, 1e-10))`, опорная мощность 1 |
| Массивы | float32 |

Одно окно — `[1,64,397]`, батч CNN — `[B,1,64,397]`. Короткие записи дополняются нулями справа.
При оценке длинных записей — окна с шагом 2 секунды и обязательным последним окном, заканчивающимся
в конце записи. Усредняются softmax-векторы окон; в метриках на исходный файл приходится один голос.
Для обучения длинных файлов на этапе 2 используется случайное окно из сохранённого waveform.

GUI показывает спектр всей записи. Для предсказания CNN используется оконная обработка. Кеш сохраняет waveform и все
детерминированные окна. Удаление пауз, denoising и нормировка громкости по максимуму не применяются.

### 1.4. MFCC для GMM и SVM

По всей реальной записи, без дополнения до 4 секунд, применяется тот же STFT/Mel и ортонормированное
DCT-II от Log-Mel. Берутся 13 коэффициентов C0…C12. Добавляются delta и delta-delta — регрессионные
производные с радиусом 2 кадра и повторением краёв. Всего **39 признаков на кадр**.

- GMM получает матрицу `[T,39]`. Предсказание и метрики относятся к исходному файлу, не к кадрам.
- SVM получает среднее и population std каждого признака по времени — **78 чисел на запись**.

### 1.5. Train-нормализация и кеш

Для каждого разбиения собственные mean/std, вычисленные исключительно по train:

- CNN — по Mel-полосам первого детерминированного окна каждой train-записи.
- GMM — по 39 признакам на реальных train-кадрах.
- SVM — по 78 признакам на train-векторах.

Используется `ddof=0`, std ограничивается снизу `1e-6`. Validation, test и все шумовые условия
используют эти же статистики. Кеш содержит ненормированные признаки, общие для обоих протоколов.

Артефакты: `data/prepared/<fingerprint>/`. Fingerprint зависит от манифеста, конфига, кода обработки,
версий библиотек и источника шума. Указатель `data/prepared/current.json` появляется только после
успешного завершения. Повторный запуск проверяет и переиспользует кеш этого набора.

### 1.6. Шумовой тест

Семь условий для каждого test-файла: **clean; white 20/10/0 dB; background 20/10/0 dB**.
Белый шум генерируется PCG64 Gaussian. Реальный фон — запись кондиционера
`noise_test/AirConditioner_1.wav` из [Microsoft MS-SNSD](https://github.com/microsoft/MS-SNSD).
Источник используется только для test. URL, commit, SHA-256 и сведения о лицензиях сохранены
в `configs/background_source.json` и `THIRD_PARTY.md`.

SNR считается по полной записи после mono/resample, с естественными паузами, до padding и окон.
Это full-clip SNR. Для одного файла используется одинаковый шумовой вектор на всех SNR.
Seed выводится SHA-256 из file_id, noise_id и replica_seed. Если файл входит в test обоих
протоколов, его шумовые версии совпадают.

В `noise_manifest.csv` записываются split, file_id, условие, SNR, seed, смещение в фоновом WAV,
alpha, измеренный SNR и SHA-256 смеси. Каждая смесь численно проверяется, затем повторно
восстанавливается из CSV и проверяется по хешу. `PreparedDataset.noisy_audio()` восстанавливает
waveform по запросу; `features()` рассчитывает признаки этого waveform для любой модели.

Для прослушивания сохраняются 42 float WAV — шесть эмоций × семь условий. Все семь версий одной
записи имеют общий коэффициент громкости для безопасного воспроизведения без перегрузки.
В эксперименте используется исходная float-смесь без clipping. Нулевая мощность вызывает ошибку.

Текущий объём — одна реализация шума на файл и один реальный фоновый исходник. Расширение —
независимые фоновые записи и три replica_seed. Копии не считаются независимыми дикторами.
Шумовая train-аугментация — отдельный эксперимент с другими шумовыми исходниками.

**Приёмка:** все признаки подготовлены; разбиения без утечек; train-статистики сохранены;
все шумовые рецепты восстановлены с правильным SNR; GUI продолжает работать.

## Этап 2. Модели и подбор параметров

### 2.1. CNN — Галкин

1. Dataset поверх подготовленного набора; train random crop для длинных файлов, validation
   с агрегацией окон на уровне записи.
2. Три блока `Conv2d(3×3,padding=1) → BatchNorm → ReLU → MaxPool(2)` с каналами 32/64/128,
   затем `AdaptiveAvgPool → Dropout → Linear(128,6)`.
3. `CrossEntropyLoss` получает logits. Softmax нужен при выводе и усреднении окон. AdamW,
   исходно lr=0.001, weight_decay=0.0001, batch_size=32, максимум 40 эпох в первом полном эксперименте.
4. Проверить градиенты, форму `[B,6]`, переобучение малой train-подвыборки, сохранение checkpoint.
5. Поиск на speaker-validation: lr {0.001,0.0003}, dropout {0.2,0.4}, фиксированный weight_decay=0.0001.
   Четыре конфигурации с одинаковым бюджетом. Расширение поиска выполняется отдельным экспериментом.
6. Early stopping по validation macro-F1, patience=8; при равенстве — меньший loss и ранняя эпоха.
   Сохранять train/validation loss, macro-F1, UAR, время, seed и лучший checkpoint.

### 2.2. GMM и собственный EM — Леончук

1. По отдельной смеси с диагональной ковариацией на каждый класс, обучаемой на его нормированных
   train-кадрах MFCC. E-step и M-step реализовать на NumPy. Готовый GaussianMixture не использовать
   в рабочей реализации; допускается как независимая проверка на синтетических данных.
2. Устойчивые log-density и log-sum-exp, нижняя граница дисперсии, обработка почти пустых компонент,
   предел итераций и критерий сходимости. Вычисления батчами для ограничения памяти.
3. Для первого бюджета ограничить число train-кадров одной записи детерминированной выборкой
   до 80 кадров; лимит заранее фиксируется в конфиге для всех классов. Validation использует все кадры.
4. K {2,4,8,16}, variance_floor {0.001,0.01}. Несколько инициализаций: лучшая по train log-likelihood,
   а K/floor выбираются по validation macro-F1.
5. Оценка записи: сумма log-likelihood реальных кадров для каждого класса плюс log prior.
   Базовые priors равномерные. Деление всех шести сумм на число кадров не меняет argmax при равных
   priors; усреднённые scores удобны для отображения. Их softmax не считать калиброванной вероятностью.
6. Проверить суммы весов и ответственностей, положительные дисперсии, сходимость на синтетической
   смеси, отсутствие NaN, восстановление сохранённой модели. Реинициализации компонент логировать:
   обычная гарантия монотонности EM при этом требует отдельного рассмотрения.

### 2.3. SVM — Леончук

1. 78 train-нормированных статистик MFCC на файл.
2. RBF SVC: C {0.1,1,10,100}, gamma {scale,0.001,0.01}; исходно class_weight=None.
   Балансировку оценивать отдельным validation-экспериментом.
3. Выбирать по speaker-validation macro-F1. Для baseline достаточно `probability=False`.
   Показывать decision scores либо отдельно калибровать по validation, не по test.
4. Сохранить модель, порядок классов, параметры признаков и train-нормализацию.

### 2.4. Общий протокол обучения

Параметры каждой модели выбираются на speaker-validation и фиксируются для обоих разбиений.
Каждая модель обучается на соответствующем train со своими статистиками. Лучший CNN checkpoint
выбирается по validation своего протокола. Test не участвует в подборе.
Подготовка тестовых признаков/шума на этапе 1 не оценивает модель и не определяет её настройки.

Финальные CNN/GMM запуски — seed 17/29/43 при неизменных split. Детерминированную SVM повторять
ради разброса по seed не требуется. До серии замерить время короткого запуска; уменьшение бюджета
должно быть объявлено до оценки test. Сохранить все validation-результаты.

**Приёмка:** обучены шесть комбинаций модель × split, для CNN/GMM есть повторы по seed;
checkpoints восстанавливаются, настройки объяснены, журналы содержат реальные значения.

## Математика для пояснительной записки

Каждую формулу связать с кодом и конкретным примером.

- STFT: `X(m,k)=Σ_n x[n+mH]w[n]exp(−j2πkn/N)`, `P=|X|²`. Hann, шаг и разрешение.
- Mel: `mel(f)=2595 log10(1+f/700)`, `M_b=Σ_k H_b(k)P_k`, `L_b=10 log10(max(M_b,10⁻¹⁰))`.
- MFCC: `c_q=a_q Σ_b L_b cos[πq(b+1/2)/B]`, `a_0=1/√B`, `a_q=√(2/B)` при q>0.
  Объяснить C0 и производные по времени.
- SNR: `10 log10(P_x/P_n)`, `y=x+αn`, `α=√(P_x/(P_n·10^(SNR/10)))`.
  0 dB — равные мощности; 20 dB — отношение 100.
- Свёртка: `Y[o,i,j]=b[o]+Σ_cuv W[o,c,u,v]X[c,i+u,j+v]`. Conv2d использует взаимную корреляцию.
- Softmax: `p_k=exp(z_k−max(z))/Σ_j exp(z_j−max(z))`; CE: `L=−mean(log p_y)`.
  Для одного примера `∂L/∂z_k=p_k−1[k=y]`.
- Градиентный спуск: `θ←θ−η∇L`, цепное правило; отдельно моменты AdamW и weight decay.
- Гауссово распределение: `N(x|μ,Σ)=(2π)^(-d/2)|Σ|^(-1/2)exp(−(x−μ)ᵀΣ⁻¹(x−μ)/2)`.
- Смесь: `p(x|c)=Σ_k π_ck N(x|μ_ck,Σ_ck)`, `π≥0`, `Σπ=1`. Диагональная Σ — предположение модели.
- E-step: `r_ik=π_k N(x_i|μ_k,Σ_k)/Σ_j π_j N(x_i|μ_j,Σ_j)`.
- M-step: `N_k=Σ_i r_ik`, `π_k=N_k/N`, `μ_k=Σ_i r_ik x_i/N_k`,
  `σ²_k=Σ_i r_ik(x_i−μ_k)²/N_k`. Правдоподобие и критерий остановки.
- Байес: `argmax_c [log p(c)+Σ_t log p(x_t|c)]`. Независимость кадров — приближение.
- SVM: зазор, soft margin с C, RBF `K(x,x′)=exp(−γ||x−x′||²)`.
- Macro-F1: среднее F1 шести классов. UAR: среднее recall. Фиксировать `zero_division=0`.
