# Этап 2 — запуск обучения вручную

Скрипты CNN, собственного GMM/EM и SVM готовы. Установлены PyTorch 2.11.0+cu128 и scikit-learn 1.9.1.
Проверена работа CUDA в `.venv` на NVIDIA GeForce RTX 4060 Laptop GPU, 8 ГБ.
Полный подбор и финальные обучения запускает пользователь. Проверочные запуски не считаются завершением этапа 2.

## Где выполнять команды

Открыть PowerShell и перейти в каталог проекта:

```powershell
Set-Location 'C:\Users\Asus\Documents\ChatGPT\omoproject'
```

Везде вызывается Python из `.venv`, активация окружения не требуется.

## Проверка окружения

```powershell
.\.venv\Scripts\python.exe -m tools.check_training
```

Ожидается `cuda_available: true`, имя RTX 4060, `torch_cuda_runtime: "12.8"` и 5 151 train-файл.
Эта проверка уже выполнена. Версия CUDA в `nvidia-smi` отражает возможности драйвера, а
`torch.version.cuda` — runtime, с которым собран PyTorch. Эти строки не обязаны совпадать.

## Полное обучение

Одна команда последовательно выполняет весь этап:

```powershell
.\.venv\Scripts\python.exe -u -m tools.train_models --device cuda
```

Порядок — SVM → GMM → CNN. GPU используется для CNN; GMM и SVM работают на CPU.
Или запускать по отдельности, дожидаясь завершения каждой команды:

```powershell
.\.venv\Scripts\python.exe -u -m tools.train_models --models svm --device cuda
.\.venv\Scripts\python.exe -u -m tools.train_models --models gmm --device cuda
.\.venv\Scripts\python.exe -u -m tools.train_models --models cnn --device cuda
```

Общий конфиг — `configs/training.json`. Для первого полного эксперимента бюджет задан заранее:

| Модель | Поиск по speaker-validation | Финальные запуски |
|---|---|---|
| SVM | 12 комбинаций C/gamma | Два split, один детерминированный запуск на каждый |
| GMM | 4 значения K × 2 variance floor, по 2 EM-инициализации | Два split × seed 17/29/43 |
| CNN | 2 learning rate × 2 dropout, weight_decay=0.0001 | Два split × seed 17/29/43 |

CNN: batch_size=32, максимум 40 эпох, early stopping patience=8, AMP на CUDA.
GMM: до 60 EM-итераций, абсолютный допуск 0.001 по среднему log-likelihood на кадр,
не более 80 равномерно выбранных train-кадров на запись. При validation используются все кадры.
Ковариации диагональные. K={2,4,8,16}, variance_floor={0.001,0.01}.

Лучший speaker-запуск с seed 17 переиспользуется как финальный. Всего при полном выполнении:
13 SVM-обучений, 13 GMM-классификаторов и 9 CNN-обучений, включая подбор.
В финальную сводку входят 14 моделей: 2 SVM, 6 GMM, 6 CNN.

Test не загружается и не оценивается. Все печатаемые `val_F1` и `validation F1` относятся к validation.
Сопоставление с тестовыми и шумовыми условиями — этап 3.

## Время и пробный запуск

На текущем ноутбуке проверочный запуск дал следующие ориентиры:

| Работа | Оценка времени |
|---|---:|
| SVM, весь предусмотренный поиск и два разбиения | 1–5 минут |
| GMM, поиск и финальные повторы | 10–20 минут |
| CNN, одна эпоха | 19 секунд по замеру второй эпохи |
| CNN, одно обучение до 40 эпох | Около 13 минут |
| CNN, весь поиск и финальные повторы | До примерно 2 часов при достижении лимитов эпох |
| Все три модели | Заложить около 2–2,5 часов |

Это оценка по короткому запуску. Ранняя остановка может сократить время, изменение частот и температуры
ноутбука — увеличить. Первая загрузка признаков заняла около минуты; повторная была быстрее.
Подробные измерения находятся в `reports/training_time_estimate.json`.

Короткая функциональная проверка трёх моделей:

```powershell
.\.venv\Scripts\python.exe -u -m tools.train_models --mode smoke --device cuda
```

Используются 48 train- и 24 validation-записи. Это проверка выполнения, не оценка качества.

Замер скорости на полном train и validation, без полного подбора:

```powershell
.\.venv\Scripts\python.exe -u -m tools.train_models --mode benchmark --device cuda
```

Он выполняет один SVM-запуск, один GMM-запуск с K=8 и пятью EM-итерациями, две эпохи CNN.
Результат — `reports/training_time_estimate.json`. Время второй эпохи CNN экстраполируется на
максимум 40 эпох и девять запусков. Early stopping может сократить время. Для GMM оценка приблизительная:
число компонент, инициализации и сходимость меняют скорость. SVM оценивается по одному C/gamma.
Загрузка признаков, сохранение checkpoints и изменение температуры/частоты GPU добавляют накладные расходы.

Для замеров ноутбук должен работать от питания. Во время длительного обучения отключить переход
в сон и запускать команды последовательно. Закрывать графический интерфейс проекта необязательно.

## Остановка и продолжение

Остановить — Ctrl+C в PowerShell. Затем выполнить **ту же команду** с тем же конфигом и кодом.

- Завершённые конфигурации переиспользуются после сверки SHA-256 модели.
- CNN продолжает с последней сохранённой эпохи: веса, optimizer, AMP scaler и RNG сохранены в `last.pt`.
- Если остановка пришлась на середину эпохи, она запускается заново.
- Незавершённый GMM/SVM-запуск начинается заново; уже завершённые конфигурации сохраняются.

Изменение параметров, кода, версий библиотек, устройства или подготовленного набора создаёт новый
каталог эксперимента. Старые результаты остаются на диске. Не менять эти файлы посреди серии.
Повторный smoke/benchmark с неизменными параметрами также переиспользует готовые результаты.

## Где результаты

В начале выводится каталог `runs/stage2_full_<id>/`. В нём:

- `manifest.json` — конфиг, версии, устройство, fingerprint данных и хеши кода.
- `<model>/selection.json` — результаты всех проверенных гиперпараметров на validation.
- `<model>/selected.json` — выбранная конфигурация.
- `<model>/<split>/<run>/metadata.json` — параметры, классы и train-нормализация.
- Для CNN: `best.pt`, `last.pt`, `history.json`.
- Для GMM: `model.npz`, `em_history.json` с ходом всех EM-инициализаций.
- Для SVM: `model.joblib`.
- В каждом запуске: `validation_predictions.csv`, `result.json`.

После выполнения всех трёх моделей и обоих разбиений в `reports/stage2_full.json`
появится `stage2_complete: true`; `runs/stage2_current.json` укажет завершённую серию.
До этого показатели smoke/benchmark не подменяют итоговые результаты.

SVM выбирает класс своим `predict` (парное голосование). Argmax отображаемых OVR-scores может
отличаться от этого класса. GMM scores — средние логарифмические оценки, а не вероятности.
CNN сохраняет softmax-оценки после усреднения окон одной исходной записи.
