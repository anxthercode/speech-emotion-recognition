Проверено 14 ноября 2026 года. Рассмотрено полное ТЗ для обоих участников. Проверка относится к набору `d39e9ad9be594911` и обучению `stage2_full_2bf7b0d2faf6`.

**Вывод.** Основные программные требования реализованы и выполнены на настоящих данных. Есть обученные CNN, собственный GMM/EM и SVM, два разбиения, чистый и шумовой тест, сохранённые предсказания, отчёт и работающее Qt-приложение. В проверенных формулах и пересчёте метрик ошибок не обнаружено. До окончательной защиты следует уточнить независимость случайного эксперимента, улучшить обработку записей без речи и представление экспериментов в GUI.

Это не пересечение train/test внутри финального random-обучения, но зависимость возникает на предыдущем этапе подбора. Основной speaker-test изолирован от собственного подбора и этим замечанием не затронут. Размер и направление возможного смещения random-метрик по текущим данным установить нельзя.

## Как происходило обучение

**Подготовка.** Метка эмоции взята из имени WAV. Используется заданная актёру эмоция, а не голосование слушателей. Исходное аудио приводится к моно и 16 кГц. Разбиение выполняется до нарезки окон и добавления шума. Стандартизация отдельно обучается на train каждого протокола. Источник содержит постановочную английскую речь, что соответствует [описанию CREMA-D](https://github.com/CheyneyComputerScience/CREMA-D).

**CNN.** Короткая запись дополняется справа нулями до четырёх секунд. При обучении длинной записи выбирается случайное четырёхсекундное окно на эпоху. При validation/test длинная запись покрывается окнами с шагом две секунды и обязательным последним окном, вероятностные выходы окон усредняются. Вход — `[batch, 1, 64, 397]`. Три блока `Conv2d → BatchNorm → ReLU → MaxPool` имеют 32/64/128 каналов. Затем глобальное усреднение, dropout и линейный слой на шесть классов.

Обучение использует cross-entropy по logits и AdamW. Softmax применяется при предсказании и объединении окон. Максимум 40 эпох, остановка после восьми эпох без улучшения validation Macro-F1. Выбирается лучший validation-чекпойнт. Было проверено четыре комбинации learning rate `{0.001, 0.0003}` и dropout `{0.2, 0.4}`. Победили **lr=0.0003, dropout=0.4, weight_decay=0.0001, batch_size=32**.

**GMM.** Для каждой эмоции объединяются её train-кадры MFCC. Чтобы ограничить вычисления и вклад длинных файлов, из каждого train-файла берётся не более 80 равномерно расположенных кадров. Validation/test используют все реальные кадры. На каждый класс обучается отдельная смесь. E- и M-шаги написаны на NumPy. Для каждой конфигурации — две инициализации, выбор по train log-likelihood. Между конфигурациями выбор по validation Macro-F1. Проверены K `{2,4,8,16}` и нижняя граница дисперсии `{0.001,0.01}`. Выбраны **K=8, variance_floor=0.01**.

**SVM.** Из 39 MFCC-признаков вычисляются средние и стандартные отклонения по времени — 78 чисел. Они стандартизуются по train. Проверены 12 сочетаний C `{0.1,1,10,100}` и gamma `{scale,0.001,0.01}`. Выбраны **C=100, gamma=0.001**, RBF-ядро. Вероятностная калибровка не включалась.

**Повторы.** CNN и GMM обучены с seed 17/29/43 для каждого разбиения. SVM детерминирована в используемом режиме и обучена один раз на разбиение. Итого 14 финальных моделей. С учётом поисковых конфигураций сохранено 35 обучений — 9 CNN, 13 GMM и 13 SVM. Лучший поисковый speaker-запуск одновременно используется как финальный seed 17.

**Фактическое оборудование и время.** Манифест фиксирует Python 3.12.10, PyTorch 2.11.0+cu128 и NVIDIA GeForce RTX 4060 Laptop GPU. CNN использовала CUDA и AMP. GMM/SVM работали на CPU. Сумма сохранённых времён fit всех 35 обучений — примерно **36,5 минуты**, из них CNN около 33 минут. Это не полное время с подготовкой данных, импортом библиотек, чтением кеша и оценкой.

## Проверка математики

| Узел | Реализованное вычисление | Оценка |
|---|---|---|
| STFT | Окно periodic Hann 400 отсчётов внутри FFT 512, шаг 160, без центрирования записи | Согласовано с `torch.stft` |
| Мощность | `P = abs(FFT)²` | Верно, поэтому логарифм мощности имеет множитель 10 |
| Mel | `2595 log10(1 + f/700)`, 64 треугольных фильтра, 50–7600 Гц, нормировка площади Slaney | Согласовано с заданной конфигурацией |
| Log-Mel | `10 log10(max(M, 1e-10))` | Верно. Это не измерение физического звукового давления в дБ SPL |
| MFCC | Orthonormal DCT-II по Mel-полосам, первые 13 коэффициентов | Проверено явной матрицей DCT |
| Производные MFCC | Регрессионная delta с радиусом 2, затем delta от delta | Верно. Значения на кадр, без деления на секунды |
| SNR | `10 log10(mean(x²)/mean(n²))` | Считается на реальной длине записи, до нулевого дополнения |
| Смешивание | `y = x + alpha*n`, `alpha = sqrt(Px/(Pn*10**(SNR/10)))` | Численно проверено, экспериментальные смеси не обрезаются по амплитуде |
| Свёртка CNN | Conv2d, фактически пространственная взаимная корреляция с обучаемым ядром | Стандартное определение слоя PyTorch |
| Softmax / CE | CrossEntropyLoss получает logits, softmax — только при выводе | Верно. Производная `p − one_hot(y)` подтверждена |
| Оптимизация | AdamW, backpropagation, отдельное weight decay | Верно. В объяснении нужно назвать именно AdamW и отличать его от простого SGD |
| Гауссова плотность | Диагональная ковариация, log-density и log-sum-exp | Проверено по формуле и независимой sklearn-модели на синтетике |
| EM | Ответственности, взвешенные средние/дисперсии, веса с суммой 1 | Верно на проверенных данных, истории правдоподобия согласованы |
| Байес | `argmax_c (sum_t log p(x_t|c) + log(1/6))` | В коде вся оценка делится на число кадров, argmax сохраняется |
| SVM | SVC RBF, предсказание через `predict`, отдельные scores через `decision_function` | Корректно учитывается голосование SVC |
| Метрики | Среднее F1/recall по фиксированным шести классам, accuracy по файлам | Все опубликованные числа восстановлены из предсказаний |

Отрицательные GMM-оценки корректны. Это средняя логарифмическая оценка плотности с априорным членом, а не процент уверенности. Числа разных моделей напрямую не сравниваются. У SVM `predict` в случае равенства голосов может отличаться от argmax отображаемых OVR scores, что описано в [документации SVC](https://scikit-learn.org/stable/modules/svm.html#scores-and-probabilities). Softmax CNN не является проверенной вероятностью правильного ответа на произвольной записи. Требования logits для CE и алгоритм обновления весов проверены по документации [CrossEntropyLoss](https://docs.pytorch.org/docs/2.11/generated/torch.nn.CrossEntropyLoss.html) и [AdamW](https://docs.pytorch.org/docs/2.11/generated/torch.optim.AdamW.html).

## Результаты и их смысл

| Модель | Macro-F1, speaker, чистая речь | Macro-F1, random, чистая речь | Macro-F1, speaker, кондиционер 0 дБ |
|---|---:|---:|---:|
| SVM | 0.499 | 0.500 | 0.130 |
| GMM | 0.452 ± 0.005 | 0.401 ± 0.005 | 0.188 |
| CNN | 0.442 ± 0.041 | 0.436 ± 0.027 | 0.268 |

Знак ± означает выборочное стандартное отклонение между seed обучения. Это не доверительный интервал по дикторам. Random-столбец требует оговорки о подборе параметров, указанной в начале проверки.

На основном чистом тесте лучше SVM. При конкретном сильном фоне кондиционера CNN сохраняет больше качества. Из этого нельзя делать общий вывод о превосходстве нейросетей при любом шуме. Результаты существенно ниже безошибочного распознавания, и особенно низки при белом шуме 0 дБ.

Случайное разбиение здесь не дало устойчивого увеличения метрик. Искусственно добиваться ожидаемого превосходства random не следует. У тестов разный состав записей, параметры выбирались под speaker, а повторения seed меняют инициализацию моделей, но не списки дикторов. Для сильного вывода о влиянии новых голосов нужны повторные независимые групповые разбиения и корректно изолированный подбор.

## Что доработать в первую очередь

**1. Разделить подбор параметров по протоколам.** В `tools/train_models.py` поиск сейчас всегда начинает с `speaker` и переносит `best['parameters']` в `random`. Для двух независимо оцененных протоколов нужен поиск на train/validation каждого из них с одинаковым бюджетом. Альтернатива для сравнения строго одинаковых настроек — зафиксировать их до исследования или подобрать на отдельном development-наборе, исключённом из обоих тестов. Текущие random-результаты сохранить как отдельный эксперимент с перенесёнными настройками. Основание — независимость test от подбора, описанная в [руководстве scikit-learn](https://scikit-learn.org/stable/modules/cross_validation.html). Новую серию выбирать по validation, а увиденный test не использовать как ориентир настройки.

**2. Добавить проверку наличия пригодной речи.** На четырёх секундах нулей SVM выдала грусть, GMM — гнев, CNN — радость с softmax 38,2%. Сейчас отсутствие речи не распознаётся как отдельное состояние. Минимум — RMS и минимальная длительность, сообщение «Слишком тихая или короткая запись». Затем проверка речевой активности и количества речи. Проверка RMS не заменяет VAD и не отсекает музыку. Порог выбирать на development/validation и проверить на тихой речи. Сохранить шесть исходных эмоций модели.

**3. Сделать шумовое сравнение наблюдаемым.** `compare_waveform` возвращает оценки для смеси, но GUI продолжает воспроизводить и рисовать исходный файл. Нужен переключатель «Исходная / С добавленным шумом» для прослушивания, осциллограммы и спектрограммы, плюс видимый тип шума и SNR. Сейчас это реальное вычислительное сравнение, но неполная демонстрация обработки. Для двух спектрограмм использовать общую шкалу цвета.

**4. Показать сравнение моделей и разброс в окне экспериментов.** Сейчас выбирается одна модель за раз, а `read_metrics` сохраняет только F1/UAR/accuracy. Уже имеющиеся в CSV `n_test`, `n_seeds`, стандартные отклонения и падение F1 не отображаются. Полезны общая таблица CNN/GMM/SVM, два протокола рядом, mean ± std и число запусков, график F1 по SNR и просмотр матриц ошибок. Отдельное немодальное окно подходит для этой задачи.

**5. Подготовить воспроизводимый перенос проекта.** Matplotlib установлен на этом компьютере, но отсутствует в requirements, хотя необходим генератору отчёта. Нужен явный файл зависимостей отчёта и инструкция установки полного набора. Локальное окружение создано с `system-site-packages=true`, поэтому отдельная проверка установки в чистом venv полезнее ещё одного полного переобучения на этом же окружении. В `PLAN.md` остались устаревшие утверждения «текущий этап 1» и «сравнение трёх моделей ещё не подключено», в README — «будущем PyTorch Dataset». Их следует синхронизировать с текущим состоянием.

## Улучшения интерфейса и исследования после основных исправлений

- Сохранить Qt Widgets. Перенос на Qt Quick не решает найденных вопросов вычислений и протокола, текущих средств достаточно для таблиц, графиков и фоновой обработки.
- Оставить speaker-модель основной в распознавании. ТЗ требует сравнить два протокола в исследовании, но не обязывает выбирать протокол для каждого загруженного файла. Random оставить в окне экспериментов и CLI. В информации о модели коротко указать протокол, данные обучения и дату.
- На 1040×760 нижние эмоции уходят под независимую прокрутку. Графики при раскрытии панели не сдвигаются, что подтверждено тестами. Для демонстрации желательно помещать все шесть оценок без прокрутки, сократить постоянный поясняющий текст и перенести его в подсказку. Цвет каждой эмоции уже есть, он дублируется текстом.
- Добавить удобный показ всех трёх предсказаний на одной записи и историю последних файлов. Это не обязательное требование ТЗ, но делает различия подходов понятнее.
- Добавить управление громкостью и указание текущего устройства вывода. Сейчас громкость приложения фиксирована на 60%, используется системное устройство по умолчанию.
- В шумовом режиме первую колонку оценок назвать «Исходная». Загруженный файл сам по себе может уже содержать шум. При повторном выборе шумового условия добавляется ещё один шум, приложение не выполняет шумоподавление.
- Объяснить отличие демонстрационных WAV от исходных. В `samples` к семи вариантам одной записи применён общий коэффициент громкости для воспроизведения. Например, для `1003_DFA_ANG_XX` он равен 0.818822. Признаки чувствительны к уровню, поэтому scores такого WAV могут отличаться от scores исходного файла в тестовой таблице. Для точного воспроизведения исследовательского результата использовать исходную запись и сохранённый рецепт шума.
- Проверить гипотезы улучшения CNN отдельными validation-экспериментами. Сейчас нет шумовой train-аугментации, и это допустимо для исходного теста устойчивости. Если добавлять её, использовать другие фоновые записи и сравнить с сохранённым baseline. Рост качества заранее не гарантируется.
- Расширить тест несколькими реальными шумами и несколькими реализациями смеси. Один кондиционер характеризует только этот фон. Повторить групповые разбиения и оценить неопределённость по дикторам, если позволяет время.
- Для защиты дополнить текст примерами STFT/Mel, одного E/M-шага, SNR, softmax/CE и объяснением AdamW. Кривые train/validation loss хранятся в JSON, но текущий рисунок CNN отображает только validation Macro-F1. Добавить loss-график и UAR по SNR — они были предусмотрены планом.

Обучение запускается из CLI, окно экспериментов показывает уже рассчитанные результаты. Записи с микрофона, пакетной обработки папки, автоматического определения языка и калибровки уверенности в GUI сейчас нет. В исходном ТЗ эти возможности не требовались.

Существующий отчёт и численные артефакты сохранены. В ходе проверки исправлен тест пути Windows и созданы материалы этого аудита. Изменение экспериментального протокола и новое обучение в эту проверку не входили.
