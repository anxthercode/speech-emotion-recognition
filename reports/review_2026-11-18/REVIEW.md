## Что не так в интерфейсе

| Приоритет | Наблюдение | Предлагаемое изменение |
|---|---|---|
| Высокий | На предоставленных снимках шесть оценок не помещаются в правую панель; при прокрутке обрезается начало пояснения | Показать все шесть строк постоянно. В сворачиваемом блоке оставить только настройки шума и техническую информацию. Убрать независимую прокрутку основных результатов |
| Высокий | Сигнал и спектрограмма занимают большую часть площади, а результату тесно | Сократить высоту шапки и карточки файла, сделать осциллограмму компактнее; выделить правой панели достаточную ширину и высоту. При малом окне разрешать общую прокрутку, сохраняя читаемость результатов |
| Высокий | При добавлении шума меняется предсказание, но проигрыватель и оба графика показывают исходный файл | Добавить «Исходная / С шумом» для прослушивания и графиков, видимые тип шума и SNR. Для сравнения спектрограмм сохранить общую шкалу цвета |
| Средний | «Параметры и оценки» смешивает управление анализом и результат; у кнопки нет явного вида раскрытого состояния | Назвать блок «Настройки анализа», показать шеврон и состояние раскрытия. Оценки перенести из него в постоянный блок результата |
| Средний | Длинное объяснение SVM/GMM занимает место перед таблицей | Короткая подпись «Оценка модели»; объяснение доступно по кнопке «Оценки: как читать». Оно должно открываться и с клавиатуры, не только при наведении |
| Средний | «Открыть запись» и «Распознать эмоцию» имеют одинаковый сильный акцент | В пустом окне выделять открытие файла; после загрузки — распознавание. Экспорт и эксперименты оставить второстепенными действиями |
| Средний | Белый текст синей кнопки при наведении имеет недостаточный контраст по выбранному ориентиру | Затемнить hover-цвет и повторно проверить все состояния, включая фокус. Не требуется менять всю палитру |
| Средний | Окно экспериментов показывает одну модель за раз и скрывает уже рассчитанный разброс | Сводная таблица CNN/GMM/SVM, оба протокола, число запусков, mean ± std, число тестовых записей; график F1 по SNR и матрицы ошибок |
| Низкий | Громкость фиксирована на 60%, текущее устройство не видно | Компактный регулятор, mute, название устройства в настройках. Добавить пробел для воспроизведения, не перехватывая его в активном поле ввода |

Цвета эмоций стоит сохранить как дополнительный признак. Название эмоции и выделение победителя должны работать и без различения цветов. Для CNN допустима диаграмма процентов с подписью «Оценки CNN». Отрицательные GMM/SVM scores — нормальные внутренние оценки, а не отрицательная вероятность. Превращать их в проценты простой нормировкой нельзя. Числа CNN, GMM и SVM не находятся на общей шкале уверенности.

Предлагаемая компоновка: сверху компактная строка файла и действий; слева проигрыватель с осциллограммой и ниже спектрограмма; справа выбор модели, распознавание, крупная предсказанная эмоция, все шесть оценок и отдельные настройки анализа. Результаты экспериментов оставить отдельным немодальным окном с заметной кнопкой открытия. Qt Widgets для этого достаточно.

### Измерения и дизайн-ориентиры

Контраст вычислен по исходным цветам QSS, а не по сглаженным пикселям снимка:

| Пара | Контраст |
|---|---:|
| Основной текст `#eaeaf2` / панель `#111114` | 15.75:1 |
| Второстепенный текст `#a8a8be` / панель | 8.09:1 |
| Приглушённый текст `#85859a` / панель | 5.22:1 |
| Белый / кнопка `#3968df` | 4.98:1 |
| Белый / hover `#4677f0` | **4.07:1** |

Для обычного текста использован ориентир 4.5:1 из [WCAG Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). Это полезная измеримая проверка для desktop, а не утверждение о полной сертификации приложения по WCAG.

[Fluent 2 Layout](https://fluent2.microsoft.design/layout) помогает унифицировать отступы и группировку: разумна шкала 4/8/12/16/24, с исключениями для оптического выравнивания. В текущем коде встречаются произвольные 15/17/19 — сами по себе они не ошибка, но усложняют согласованность. [Fluent 2 Button](https://fluent2.microsoft.design/components/web/react/core/button/usage) даёт ориентиры для иерархии действий и явного состояния переключателей. [Fluent 2 Typography](https://fluent2.microsoft.design/typography) полезна для небольшого набора размеров текста; переход с текущих 13 px к 14 px можно проверить вместе с новой компоновкой, а не увеличивать шрифт в уже тесной панели. Видимость состояния и узнаваемость элементов также согласуются с [эвристиками Nielsen Norman Group](https://www.nngroup.com/articles/ten-usability-heuristics/).

Численные результаты — в [checks.json](checks.json), проверки приложения — в [gui_checks.json](gui_checks.json).

- Заново проверены оба разбиения, их воспроизводимость, отсутствие пересечения файлов внутри каждого протокола и отсутствие пересечения дикторов в speaker. В каждой схеме 5 151 train, 1 142 validation и 1 142 test.
- Заново рассчитаны Log-Mel, MFCC и SVM-признаки всех **7 435 записей**: совпадают с сохранёнными значениями. Статистики нормализации рассчитаны только по train; максимальное отличие независимого пересчёта менее `1.4e-11`.

- STFT/Log-Mel сверены с реализацией STFT PyTorch: максимальное отличие `1.39e-6` дБ. MFCC сверены с явной ортонормированной матрицей DCT: `1.61e-5`. Градиент cross-entropy совпадает с `softmax − one_hot`.
- 24 теста успешно завершились. Среди них: формула гауссовой плотности, log-sum-exp, EM с независимым эталоном, ограничение дисперсии, CNN logits/градиенты, сохранение весов, продолжение обучения и метрики при отсутствующем предсказанном классе.

## Что остаётся исправить по существу

1. **Независимость случайного эксперимента.** Подбор был выполнен на speaker-validation, выбранные параметры перенесены в random. Из 1 142 записей random-test 183 ранее участвовали в speaker-validation, 786 — в speaker-train. Внутри финального random-разбиения пересечения train/test нет, но его тест не полностью независим от предыдущего подбора. Основной speaker-test этим не затронут. Нужен отдельный подбор внутри каждого протокола либо общий development-набор вне обоих тестов. Существующие random-результаты следует сохранить с этой оговоркой. Сравнение протоколов требуется в ТЗ; убирать random из исследования нельзя.
2. **Записи без речи.** Четыре секунды нулей получают эмоцию: SVM — грусть, GMM — гнев, CNN — радость с оценкой 38.2%. Нужна проверка пригодности сигнала и речевой активности. Порог тишины не следует выбирать так, чтобы отбрасывать тихую речь; RMS сам по себе не заменяет VAD.
3. **Наблюдаемое сравнение с шумом и полная таблица экспериментов.** Расчёт работает, представление неполное — изменения описаны выше. Это не повод заменять реальные scores искусственными процентами.
4. **Границы результатов.** Один реальный фон — кондиционер — не характеризует устойчивость ко всем фоновым шумам. CREMA-D содержит постановочную английскую речь; качество на произвольной русской записи отдельно не проверено. Три seed меняют обучение, но не дают три независимых разбиения по дикторам.

Основные требования полного ТЗ реализованы: CNN/PyTorch на Log-Mel, MFCC, собственный GMM/EM на NumPy, SVM/scikit-learn, подбор, два протокола, шумовой тест, метрики и GUI. Для корректного завершения исследовательской части приоритетен пункт 1. Подробности обучения и результатов сохранены в [предыдущем аудите](../audit_2026-11-14/REVIEW.md) и [итоговом отчёте](../stage3/REPORT.md).
