# Распознавание эмоций по голосу — CNN, GMM и SVM

Проект Галкина В. А. и Леончука Е. Д. включает подготовку данных, обучение CNN, GMM и SVM, оценку на чистых и зашумлённых записях и приложение на Qt Widgets / PySide6. Сравнение моделей и графики находятся в [итоговом отчёте](reports/stage3/REPORT.md). План и формулы приведены в `PLAN.md`.

Проверка кода, всех данных и метрик от 14 ноября 2026 года — в [отчёте аудита](reports/audit_2026-11-14/REVIEW.md). В нём отмечено ограничение случайного эксперимента: настройки перенесены со speaker-validation, часть записей которого входит в random-test. Для независимого сравнения нужен отдельный подбор внутри каждого протокола. Основной speaker-test изолирован от собственного подбора.

Повторная проверка расчётов, разбор интерфейса и реестр очистки от 18 ноября — в [актуальном обзоре](reports/review_2026-11-18/REVIEW.md).

**CREMA-D загружен и проверен.** Для разбиений готовы 7 435 записей от 91 диктора в `data/metadata.csv`. Причины исключения остальных записей сохранены в `data/exclusions.csv`. Команда повторного аудита и порядок подготовки данных описаны в `DATASET_NEXT_STEPS.md`.

## Этап 1 — подготовка всех данных

Фактические количества файлов, дикторов, окон и шумовых проверок — в `reports/stage1.md` и `reports/stage1.json`.
Команды из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m tools.fetch_background
.\.venv\Scripts\python.exe -m tools.prepare_data
```

Первая команда проверяет или скачивает один небольшой WAV фонового шума из MS-SNSD по фиксированному URL и SHA-256.
Вторая проверяет аудио, сохраняет speaker/random-разбиения, признаки всех пригодных файлов, train-нормализацию
и тестовые шумовые рецепты. Повторный запуск переиспользует кеш с тем же fingerprint. Исходные WAV сохраняются.

В `data/prepared/current.json` указан каталог завершённого набора. Его содержимое:

- `splits/speaker.csv`, `splits/random.csv` — общие разбиения для трёх моделей.
- `features/*.npz` — waveform 16 kHz, Log-Mel `[окна,64,397]`, MFCC `[кадры,39]`, SVM-вектор `[78]`.
- `feature_index.csv`, `config.json`, `preprocessing.json`, `labels.json` — описание и привязка признаков.
- `normalization/speaker.json`, `normalization/random.json` — статистики только соответствующего train.
- `noise_manifest.csv` — воспроизводимые white/background смеси 20/10/0 dB исключительно для test.
- `samples/`, `samples.csv` — 42 WAV для прослушивания в существующем GUI: шесть эмоций × семь условий.
- `report.json` — состав частей, пересечения, версии, хеши и результаты проверок.

Экспериментальные смеси восстанавливаются по запросу. Для каждого рецепта уже проверены SNR и совпадение
SHA-256 повторно созданного waveform. Данные не клиппируются; демонстрационные WAV имеют одинаковый
коэффициент громкости для семи условий одного файла. Сейчас используется один реальный фон и одна
реализация каждого шума на запись. Источник и сведения о лицензировании — в `THIRD_PARTY.md`.

Программный доступ без PyTorch:

```python
from ser.dataset import PreparedDataset

data = PreparedDataset(split="speaker", subset="test")
file_id = data.records[0]["file_id"]
clean = data.features(file_id, standardize=True)
noisy = data.features(file_id, condition="background", snr_db=10, standardize=True)
print(clean["log_mel"].shape, clean["mfcc"].shape, clean["svm"].shape)
```

Для CNN ось канала добавляется загрузчиком в `ser/train_cnn.py`. MFCC рассчитываются по всей реальной записи,
без четырёхсекундного padding. В SVM-векторе средние и std рассчитаны по 39 ненормированным MFCC-признакам;
затем применяется собственная нормализация 78 статистик по train. GMM-нормализацию перед их агрегацией не применять.

## Запуск

В подготовленном окружении Windows откройте `run_gui.bat` двойным щелчком. Либо выполните из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m qt_gui
```

Для установки на другом компьютере с Python 3.12:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-gui.txt -r requirements-data.txt
.\.venv\Scripts\python.exe -m qt_gui
```

На текущем компьютере локальное `.venv` переиспользует уже установленные PySide6 и NumPy через `system-site-packages`. SciPy и SoundFile установлены в `.venv`. Проверенные версии: Python 3.12, PySide6 6.12.0, NumPy 2.5.3, SciPy 1.18.1, SoundFile 0.14.0. Глобальные пакеты не изменялись.

## Что уже работает

- Открытие WAV, MP3, FLAC, OGG и AIFF через меню «Файл», Ctrl+O или перетаскиванием одного файла в окно.
- Воспроизведение, пауза и остановка. Щелчок по волне или перетаскивание курсора меняет позицию.
- Расчёт настоящей Log-Mel спектрограммы в рабочем потоке без блокировки окна.
- Выбор CNN, GMM или SVM и цветовое выделение предсказанной эмоции. В параметрах доступны оценки классов и сравнение с шумом.
- Сохранение сведений о файле, обработке и предсказании в JSON.
- Кнопка «Эксперименты» открывает отдельное окно с метриками из `reports/stage3/test_summary.csv`. В нём доступны оба разбиения, три модели, импорт CSV и экспорт шаблона на 42 условия.

Поддерживаются записи до 60 секунд, до 64 МБ, до 8 каналов и с частотой от 8 до 192 кГц. Осциллограмма и Log-Mel показывают всю запись по одной шкале времени. Цветовая шкала спектрограммы охватывает 80 дБ относительно максимума. При распознавании CNN использует фиксированные окна с дополнением коротких записей.

Откройте аудиофайл, выберите модель и нажмите «Распознать эмоцию». Для каждой модели приложение использует
чекпойнт с наибольшим validation Macro-F1 среди финальных запусков разбиения по дикторам.
В разделе «Параметры и оценки» можно добавить шум для второго предсказания и посмотреть оценки классов.
Для CNN они показаны в процентах. У GMM более высокая логарифмическая оценка означает более подходящий класс.
В таблице экспериментов CNN и GMM
усреднены по трём запускам. Подготовленные примеры WAV находятся в `samples` внутри каталога из
`data/prepared/current.json`. Для использования сохранённых моделей нужны также зависимости из `requirements-train.txt`.

Для повторной оценки и генерации отчёта из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m tools.evaluate_models --device cuda
.\.venv\Scripts\python.exe -m tools.report_evaluation
```

Для второго шага используется Matplotlib (проверено с 3.11.2). Полный набор зависимостей отчёта устанавливается командой `.\.venv\Scripts\python.exe -m pip install -r requirements-report.txt`. Для CPU-оценки можно указать `--device cpu`.
Команда `tools.predict_emotion` принимает путь к аудиофайлу и использует те же модели, что Qt.
Команды повторного обучения и описание сохранения моделей приведены в `TRAINING.md`.

```powershell
.\.venv\Scripts\python.exe -m tools.check_training
.\.venv\Scripts\python.exe -u -m tools.train_models --device cuda
```

## Файлы

- `PLAN.md` — полный план исследования, математика, разбиения и критерии готовности.
- `configs/data.json` — единые параметры первого этапа.
- `ser/features.py`, `ser/splits.py`, `ser/noise.py` — признаки, два протокола и смешивание шума.
- `ser/statistics.py`, `ser/dataset.py` — train-статистики и загрузка подготовленных данных.
- `tools/prepare_data.py` — подготовка и проверка всего набора.
- `TRAINING.md`, `configs/training.json` — запуск и бюджет второго этапа.
- `ser/cnn.py`, `ser/gmm.py` — CNN и собственная реализация GMM/EM.
- `ser/train_cnn.py`, `ser/train_classical.py` — обучение, validation и checkpoints.
- `tools/train_models.py` — полный запуск, smoke и замер скорости.
- `qt_gui/main.py` — окно Qt, рабочий поток, воспроизведение, CSV/JSON.
- `qt_gui/audio.py` — загрузка WAV и вызов общего аудиоконвейера из `ser`.
- `qt_gui/plots.py` — графики на QPainter, без браузера и WebEngine.
- `qt_gui/theme.py` — общая графитовая палитра и стили.
- `DESIGN.md` — решения по дизайну и Qt Widgets / Qt Quick.
- `DATASET_NEXT_STEPS.md` — результат проверки ZIP, команды Git LFS и дальнейший порядок работы.
- `tools/check_crema.py` — проверка ZIP или папки AudioWAV без извлечения и изменения исходных данных.
- `tools/render_gui_preview.py` — снимки окон и HTML-предпросмотр; создаются по запросу в `reports/previews/`, а не в корне проекта.
- `tools/verify_project.py`, `tools/verify_gui.py` — повторная проверка сохранённых данных, вычислений, моделей и связи GUI с ними. Обучение не запускают.
- `tests/test_gui.py` — проверки признаков, чтения WAV, импорта метрик и рабочего потока.
- `tests/test_pipeline.py` — разбиения, защита от утечек, MFCC, SNR, воспроизводимость и train-нормализация.

CSV принимает `model,split,condition,snr_db,n_test,n_seeds,macro_f1,uar,accuracy`. Старые файлы без `model` относятся к CNN. Поддержаны `speaker/random`, `clean/white/background` и SNR 0/10/20. Для `clean` SNR оставляют пустым. Перед импортом повторные запуски усредняют по модели, разбиению и условию.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Проверки покрывают аудио и GUI, два разбиения, отсутствие утечек, MFCC и временные производные,
SNR, повторяемость шума, train-нормализацию, EM на синтетических данных, градиенты и checkpoints CNN,
а также продолжение прерванного обучения. При ограничениях Windows sandbox временные тестовые файлы
нужно направить в доступный каталог проекта вместо системного TEMP. Главное окно проверяется
при 1040×760, 1280×880 и 1920×1080. GUI-тесты работают через Qt offscreen; физическое воспроизведение не оценивается автоматически.

Полная проверка существующих артефактов (требуются все зависимости и подготовленные данные):

```powershell
.\.venv\Scripts\python.exe -B -m tools.verify_project
.\.venv\Scripts\python.exe -B -m tools.verify_gui
```

Численные результаты сохраняются в `reports/verification/`. Для сохранения технических снимков GUI добавьте `--screenshots` ко второй команде; по умолчанию изображения и пробные аудиофайлы не остаются в проекте.

HTML-предпросмотр можно восстановить командой `.\.venv\Scripts\python.exe -B -m tools.render_gui_preview`.

## Хранение файлов

Для работы и повторения экспериментов сохранены `.venv`, исходные `AudioWAV`, текущий `data/prepared`, исходник фонового шума, полное обучение из `runs/stage2_current.json` и научные отчёты. Подготовленные признаки занимают место, но сейчас используются загрузчиками обучения и оценки — удалять их как обычный временный кеш не следует.

При очистке удаляются старые макеты, технические пробные аудио, `__pycache__`, прежние smoke/benchmark-запуски и проверенные дубликаты WAV из Git LFS. `AudioMP3` и `VideoFlash` содержали только неиспользуемые LFS-указатели; их удаление не отменяет поддержку пользовательских MP3 в приложении. Файлы лицензии и метаданные CREMA-D сохранены.

После удаления локальных LFS-копий исходные WAV остаются обычными читаемыми файлами. Если потребуется заново извлечь их из Git, нужные LFS-объекты придётся повторно скачать. Не запускайте общий `git lfs pull` без ограничения `AudioWAV/*`, если MP3 и видео не нужны. Исторические JSON-отчёты smoke/benchmark оставлены как замеры времени; соответствующие пробные веса удалены.

Для снимка окна без отображения на рабочем столе:

```powershell
$env:QT_QPA_PLATFORM = 'offscreen'
.\.venv\Scripts\python.exe -m qt_gui --screenshot preview.png
Remove-Item Env:QT_QPA_PLATFORM
```

PySide6 — официальные Python-привязки Qt: [документация Qt for Python](https://doc.qt.io/qtforpython-6/index.html).
